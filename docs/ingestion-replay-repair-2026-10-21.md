# 수집 재실행 실패 원인과 수정 (2026-10-21)

## 확인된 원인

법제처의 서버 장애로 단정할 근거는 없다. run `39435908498`에서는 같은
runner의 직접/WARP 연결과 실제 최신 선고 조회가 성공했다. 그 뒤 수집이
로컬 원문·서빙 정책 경계에서 중단됐다.

1. `MasterDB.upsert_raw()`가 격리 ID라는 이유만으로 원문 변경 오류를 냈다.
   보관 원문의 고정 해시와 새 원문을 비교하지 않아 동일 재수집도 실패했다.
2. 원문을 유지하고 정정본으로 서빙하는 복구 행에도 같은 문제가 있었다.
   원문/정정본의 관계를 재검증해 쓰기 없이 재사용하는 경로가 필요했다.
3. 원천의 명시적 `대법원2026두31124` 표기를 지원하지 않았다. 법원 약칭을
   추정하거나 병합 목록의 일부만 취하는 처리는 추가하지 않았다.
4. 헌재의 종국일자 `0`을 잘못된 달력 날짜로 처리했다. 기존 저장·압축·기간
   커버리지 정책의 미상 sentinel로 원문 그대로 보존하고, 기존 정상 날짜를
   미상 값으로 덮지 않는다. 다른 잘못된 날짜는 계속 실패한다.
5. 보관 DB와 API 목록의 날짜 표시 형식이 다를 수 있다. 달력 검증을 통과한
   같은 날짜에만 형식 동등성을 허용하며 원문의 날짜 문자열은 바꾸지 않는다.

## 무결성 경계

- 수집 시작 시 검증한 격리 inventory를 읽기 전용 재수집 검사기로 사용한다.
  대상 행은 매번 다시 읽어 일곱 원문 열의 고정 해시를 확인한다.
- ID·사건명·사건번호·법원은 완전히 같아야 한다. 날짜만 검증된 달력 날짜의
  표시 형식 차이를 허용한다. 실제 변경은 기존 오류와 durable backlog를 유지한다.
- 동일한 역사적 격리 원문은 현행 파서가 해석하지 못해도 격리를 유지한 채
  무변경 처리한다. 신규 행에는 이 예외가 없고, 페이지 count·중복 ID·범위·
  최종 export inventory/해시·reference 보존·부분 게시 차단은 그대로 검사한다.
- 검토된 복구 행은 저장 원문과 provenance를 다시 대조한다. 같은 원문 또는
  그 원문에 정확히 결합된 정정본의 재수집만 쓰기 없이 처리한다.
- 격리 해제, 원문 삭제/교체, 신규 오류 자동 격리, 법원 약칭 추정, 병합 번호
  일부 삭제, public 계약 변경, 전송 경로 fallback은 추가하지 않았다.
- API 상세 링크에는 OC 식별자가 포함될 수 있다. 내부 비교용 원문 receipt에는
  다섯 데이터 필드만 담고 URL·링크·응답 본문은 넣지 않는다.
