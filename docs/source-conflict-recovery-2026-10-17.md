## 공단 29,180행의 복구 가능성

법제처 목록에서는 모든 대상 행의 번호·법원이 비어 있고 날짜가 `0001.01.01`이다.
앞서 확인한 상세 XML도 날짜 `00010101`을 제공한다. 그러나 법제처 **원문 화면의
공단 원출처 링크**를 따라가면 사건 표제의 번호·법원·`판결선고` 필드를 확인할
수 있다. 법제처 내부의 어느 수집·매핑 단계에서 날짜가 사라졌는지는 접근 가능한
응답만으로 확정하지 못했다.

표본은 전체 원문 ID 정렬의 양 끝을 포함한 등간격 96개 위치와 기존 표본 3건으로
고정했다. 총 99개다. 확률 표본이나 전체 복구율 추정 자료는 아니다.

| 처리 | 행 수 |
| --- | ---: |
| 원출처 표제·선고일 직접 대조 후 추가 | **96** |
| 원출처에서도 선고일을 확인하지 못함 | **3** |
| 원출처 미대조 | **29,081** |
| 전체 | **29,180** |

96행 중 94행은 명시된 번호·법원·선고일을 그대로 확인했고, 2행은 별도 원문
대조를 거쳤다. ID 361482는 `(창원)`을 재판부 정보로 보존했고, ID 611985는
원문 번호 앞의 표제 라벨 `사건`과 완전한 사건번호를 분리했다. 두 원문 모두
원본 번호·URL·해시를 보존했다. 일반적인 앞글자 제거 규칙을 추가하지 않았다.

날짜는 사건 표제의 명시된 선고 필드에서만 읽었다. 본문 첫 날짜, 처분일,
변론종결일, 관련 사건의 선고일, 법제처 수집일을 대신 사용하지 않았다.
원출처 링크의 사건 ID, 원출처 표제의 번호·법원, 법제처 상세 표제의 번호를
서로 대조한 후 추가했다. 중복 라벨·공란·잘못된 날짜·필드 길이 위반은 보류한다.

예: [서울행정법원 2006구단1480 공단 원문](https://sanjaecase.comwel.or.kr/service/dataView?id=2006%EA%B5%AC%EB%8B%A81480_%EC%84%9C%EC%9A%B8%ED%96%89%EC%A0%95%EB%B2%95%EC%9B%90)의
명시된 판결선고는 **2007.06.05**다. 공란으로 계속 보류하는 표본은 ID 409398
(`2019두36292`), 412470 (`2021구단11701`), 416770 (`2022두30645`)이다.

공단의 공개 분류 목록도 확인했으나, 확인한 목록에는 개별 선고일과 법제처 ID의
직접 연결이 없어 원문별 대조를 대체하지 못했다. 전체 복구 확대는 다음 순서다.

1. `worker-population.csv`의 미대조 29,081 ID를 고정 큐로 삼는다.
2. ID별 법제처 원문 화면과 그 화면이 가리키는 공단 원출처를 대조한다.
   이번과 같은 경로라면 추가 요청은 기본적으로 **58,162 GET**이다. 현재처럼
   시작 간격 0.4초를 유지하면 간격만 약 **6시간 28분**이며 RTT·중단·backoff가
   더해진다. 실제 완료 시간·복구 성공 건수의 예측으로 제시한 값은 아니다.
3. 최대 동시 요청 2개, 캐시·URL·해시·ID별 완료 journal을 사용한다. 통신 실패와
   원출처 메타데이터 부족을 나누고, 어느 쪽도 정상 0건으로 처리하지 않는다.
4. 표제에서 날짜가 없는 항목은 원판결문 또는 동일 판결임을 입증할 다른 공식
   원문이 확보될 때까지 보류한다. 표본에서 안 된 3행도 이 큐에 남긴다.
5. 전체 대상의 완료·제외·보류 수가 일치하고 DB·provenance·export 전수 대조가
   통과한 후 운영 게시 가능 여부를 별도로 판단한다.

이번에는 복구 경로 검증과 96행의 실제 추가까지 수행했다. 나머지 29,081행의
원문 대조를 실행했거나 전체 복구가 끝났다고 보고하지 않는다.

## 회귀와 무결성 검증

- 본소·반소 실물 9건: 수정 전 모두 오류, 수정 후 모든 원문 저장·2개 키 export·

- Python 전체 **113개 통과**, Ruff `pipeline scripts` 통과.
- 복구 전용 실패 경로 **6개 통과**: 본문 날짜 배제, 표제 경계 누락, 중복 라벨,
  미검증 재판부, 길이 초과, 모호한 생략 번호의 본문 근거 누락.
- 원출처 보존 파일 **238개 해시·크기 재검증**, 전체 DB 스키마·manifest·gzip·
  canonical 전수 대조, SQLite integrity 및 498개 복구 원문의 export 대조 통과.
- 1차 후보의 **134,513개 레코드와 모든 법원 코드 보존**, 공개 기준본
  134,121개 레코드도 별도 대조. 새 법원 문자열 4개에 미사용 코드 194–197 할당.
- 실제 ZIP runtime: 전체 후보 설치, **522키 조회**, canonical **861키**와 법원
  사전·hash·version의 활성 세대 일치 통과. 전체 성능 개선 수치로 일반화하지 않음.

주장하지 않는다. 이번에 다시 실행하지 않은 Jest·전체 E2E를 신규 통과로 세지 않았다.
