# 수동 서비스 QA 프로토콜

사용자가 실제 AI 사이트의 입력·전송·조작을 담당한다. 에이전트는 프롬프트를 제시하고
전달받은 결과를 분석하며 로컬 코드와 오프라인 테스트로 문제를 수정한다.
실제 AI 사이트의 자동 입력·전송·클릭·스크롤·DOM 조회·네트워크 수집은 수행하지 않는다.
자동 점검을 재개하려면 사용자의 별도 명시 지시가 필요하다.

## 진행 순서

ChatGPT → Gemini → Claude → Copilot → Perplexity → Grok 순서로 한 사이트씩 진행한다.
각 단계를 안내하고 결과를 받은 뒤 다음 단계로 간다. 사이트당 새 테스트 대화에서
프롬프트를 한 번 사용하며 불필요한 재생성·반복 전송은 하지 않는다.
개인정보를 넣지 않고, 로그인·서비스 제한이 있으면 해당 점검을 보류한다.

1. 사용자가 새 대화를 열고 확장 버전, DB 일자·건수, 전체·사이트·법원·헌재 설정을 확인한다.
   브라우저와 모델 버전도 가능한 범위에서 기록한다.
2. 에이전트가 [표준 프롬프트](../evaluation/prompts/standard-tester.md)를 제시한다.
   사용자가 직접 붙여 넣고 전송한 뒤 완성된 표와 관찰 결과를 전달한다.
   사용자 입력문에는 배지가 없어야 하며, 중복·깜빡임은 관찰한 경우에만 기록한다.
3. 행별 표시를 아래 기준과 비교한다. 회색·누락·다른 색은 원인을 확인하고 통과 처리하지 않는다.
   DB가 갱신됐다면 오프라인 조회로 기대값부터 다시 확인한다.
4. 사용자가 1번 배지의 원문 링크를 열어 병역법위반 / 2018.11.1.을 확인한다.
   닫고 2번을 열어 일제 강제동원 손해배상 / 2018.10.30.으로 바뀌는지 확인한다.
   주황은 DB 미확인 안내, 빨강은 일련번호 0 경고인지 확인한다.
5. Tab·Enter·Escape, tooltip·뷰어 닫기와 포커스 복귀를 확인한다.
   법원 필터 OFF→ON에서 배지 제거·복원과 미전송 문구 보존을 확인한다.
   화면을 좁혀 tooltip·뷰어·닫기 버튼에 접근 가능한지 확인한 뒤 설정을 원복한다.
6. 사이트별 완료·문제 있음·보류와 미검증 항목을 [품질 평가](quality-evaluation.md)에 기록한다.
   수정이 필요하면 로컬에서 조치하고, 확인을 마친 뒤 다음 사이트를 안내한다.

## 행별 기대 판정

아래 기준은 활성 DB 20261101에서 확인했다. 기계 fixture에는 번들 20261018의
버전·해시·레코드도 별도로 기록한다. DB 미확인은 사건 부존재 판정이 아니다.

| 행 | 기대 표시 | 의미 |
| --- | --- | --- |
| 1~2 | 초록 | 현재 DB에 번호가 있음. 인용 내용 일치 판정은 아님 |
| 3~7 | 주황 | 해당 snapshot에서 DB 미확인 |
| 8 | 주황 | 하급심도 지원하며 이 번호는 DB 미확인 |
| 9 | 주황 | 두 자리 연도도 지원하며 이 번호는 DB 미확인 |
| 10 | 빨강 | 추출 후 일련번호 0을 검증 단계에서 거부 |

표준 프롬프트에는 사건번호만 넣고 기대값은 이 문서와
`evaluation/standard-tester.json`으로 관리한다.

## 결과 양식

```text
사이트 / 모델:
Chrome / 확장 버전:
DB 일자 / 건수:
단계:
행별 색 또는 문제:
사용자 입력문 배지 여부:
원문 / 키보드 / 필터 / 좁은 창:
판정: 완료 / 문제 있음 / 보류
미검증 항목:
```

## 계정 없는 반복 검증

```powershell
npm run eval:standard
npm run eval:standard -- --extension-path <압축해제한-패키지-폴더>
```

이 명령은 로컬 사건번호 모듈과 선택한 DB를 사용하며 AI 서비스에 접속하지 않는다.
자동 E2E도 격리 브라우저의 모의 페이지·네트워크로 실행한다.
실제 서비스의 DOM·스트리밍 등 합성 테스트로 확정할 수 없는 부분은 별도 수동 확인한다.
